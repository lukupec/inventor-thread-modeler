# Building ThreadModeler

## Requirements

| | |
|---|---|
| SDK | [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) |
| OS | Windows 10/11 x64 for the MSI. The add-in, tests and bundle also build on Linux/macOS. |
| IDE (optional) | Visual Studio 2026 with the **.NET desktop development** workload (VS 2022 cannot target .NET 10) |
| Inventor (only to run/debug) | Inventor 2027, or Inventor 2026 Update 2026.4+ |

WiX (for the MSI) comes as a NuGet SDK (`WixToolset.Sdk/5.0.2`), so you don't install it separately.

## Build everything

```powershell
.\build.ps1                          # Release: add-in, tests, bundle, MSI + .sha256 in dist\
.\build.ps1 -Version 30.0.2          # override the product version
.\build.ps1 -Configuration Debug -SkipInstaller -Install   # dev: copy the bundle to ProgramData (elevated prompt)
```

```bash
./build.sh                           # any OS: add-in, tests, bundle + zip (no MSI)
./build.sh Release -p:Version=30.0.2
```

Output:

```
bin/<Configuration>/                 the bundle as built (PackageContents.xml + Contents/)
dist/
  ThreadModeler-<version>.msi        installer (build.ps1 only)
  ThreadModeler-<version>.msi.sha256
  ThreadModeler.bundle/
    PackageContents.xml
    Contents/
      ThreadModeler.Inventor.addin
      ThreadModeler.dll, .deps.json, .runtimeconfig.json
      LICENSE.txt, THIRD-PARTY-NOTICES.txt
      Thread Templates/BSW Template.ipt, ISO Template.ipt
  ThreadModeler.bundle.zip
```

Individual steps:

```powershell
dotnet build ThreadModeler\ThreadModeler.csproj -c Release                    # -> bin\Release\
dotnet test  ThreadModeler.Tests\ThreadModeler.Tests.csproj
dotnet build Installer\ThreadModeler.Installer.wixproj -c Release              # needs bin\Release\, Windows only
```

## Version

The product version lives only in `Directory.Build.props` (`<Version>`). It is used for:

- the assembly version (`AssemblyVersion`/`FileVersion` are generated by the SDK),
- `PackageContents.xml`, a template in `ThreadModeler\` whose `@VERSION@` is filled in at build time,
- the MSI version and file name.

Pass `-p:Version=X.Y.Z` (or `build.ps1 -Version X.Y.Z`) to override it. The release workflow does this from the tag.
The major version follows the Inventor internal version of the first supported release (30 = Inventor 2026).

## Inventor interop reference

`Autodesk.Inventor.Interop` and `stdole` are **normal references (Embed Interop Types = false) and are not
copied to the output**. Inventor provides both at runtime. Inventor creates the add-in and casts it to its own
`Inventor.ApplicationAddInServer` type, so the add-in must use Inventor's interop type, not an embedded copy.

The compile-time reference sets the *minimum* interop version needed at runtime. The default is therefore the
old interop in `References\` (v16). Inventor 2026 (v30) and 2027 (v31) both satisfy it, and the add-in uses no
newer API. Compiling against an Inventor 2027 installation would stop the add-in loading in Inventor 2026.
Override this only when you need newer API:

```powershell
dotnet build ThreadModeler\ThreadModeler.csproj -p:InventorInteropPath="C:\Program Files\Autodesk\Inventor 2026\Bin\Public Assemblies\Autodesk.Inventor.Interop.dll"
```

## Debugging in Visual Studio

1. Build `Debug|x64` and install it as a bundle: `.\build.ps1 -Configuration Debug -SkipInstaller -Install` (elevated).
   Alternatively, create a directory junction
   `C:\ProgramData\Autodesk\ApplicationPlugins\ThreadModeler.bundle` → `<repo>\bin\Debug`, so every build is picked up.
2. The Debug configuration starts `C:\Program Files\Autodesk\Inventor 2027\Bin\Inventor.exe`.
   Change `StartProgram` in `ThreadModeler.csproj` for Inventor 2026.
3. Press F5. Breakpoints in `StandardAddInServer.Activate` are hit while Inventor starts.

Close Inventor before rebuilding, because it locks `ThreadModeler.dll`.
If loading fails, see `%LOCALAPPDATA%\ThreadModeler\ThreadModeler.log` and `%TEMP%\ThreadModeler-load-error.txt`.

**Do not add third-party NuGet dependencies lightly.** Inventor loads every add-in and its own components into one
process. If another component has already loaded a different version of the same library, .NET refuses to load
yours, and the add-in fails silently while Inventor creates it. This is what broke 30.0.1 with log4net.

To test the updater without waiting a day, delete `%LOCALAPPDATA%\ThreadModeler\update.json`
or use **Check for Updates**.

## Releasing a new version

1. Bump `<Version>` in `Directory.Build.props` and add a `CHANGELOG.md` entry. Commit and push to `master`.
2. Start the release, either way:
   - On GitHub: **Actions → release → Run workflow**, branch `master`, version `30.0.2`. This creates tag `v30.0.2`.
   - Or push a tag:
     ```bash
     git tag v30.0.2
     git push origin v30.0.2
     ```
3. `.github/workflows/release.yml` builds that version, runs the tests, and creates the GitHub release with
   `ThreadModeler-30.0.2.msi`, `ThreadModeler-30.0.2.msi.sha256` and `ThreadModeler.bundle.zip`.

Installed add-ins find the new release at their next daily check. The updater:

- reads `https://api.github.com/repos/lukupec/inventor-thread-modeler/releases/latest`,
- ignores drafts and pre-releases,
- needs the `.msi` and the matching `.msi.sha256` asset,
- needs the repository to be **public**.

If the repository is renamed or moved, update `RepoOwner`/`RepoName` in `ThreadModeler/Update/UpdateLogic.cs`.

## Continuous integration

`.github/workflows/build.yml` runs on every push and pull request, on `windows-latest`. It runs `build.ps1`,
which builds, tests and packages, then uploads two artifacts: **ThreadModeler-installer** (MSI + checksum) and
**ThreadModeler.bundle** (the bundle folder). GitHub always downloads an artifact as a zip, so unzip it once.
